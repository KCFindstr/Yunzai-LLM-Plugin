# 聊天执行记录（Rollouts）

网页管理面板的 **对话与记忆 → 执行记录**（`#/rollouts`）使用与 AGY 相同的列表和时间线布局。每次主聊天模型执行单独展示，包括排队/执行/完成/失败状态、用户输入、各轮可见模型响应、工具参数与结果、最终生成的回复，以及模型、思考强度、耗时、token 和费用。工具并行执行时，各自返回后立即记录结果。页面每三秒更新，支持筛选；“对话”的最近记录弹窗也可直接进入对应执行。执行详情中的“对话”和“向量空间”链接均指向本次执行所属会话。

新执行还会保存思考强度的选择过程：固定配置、自动判断模型（包括 Jev）的响应，或判断失败时使用的第一个类别（旧记录可能显示快速判断或关键词规则）。主动发言的执行标为「主动发言」。Jev 响应保留分类、置信度、分类概率、模型与用量；判断失败会显示回退原因。图片导致分类提高时，原始判断和实际分类分别保留。主模型接口拒绝思考设置时，显示原先选中的强度以及实际使用的强度；每轮模型响应也带有实际强度。旧记录中没有保存的信息不会用当前配置补填。

模型思考内容的返回设置：

| 接口 | 请求与记录方式 |
| --- | --- |
| [Gemini Interactions](https://ai.google.dev/gemini-api/docs/thinking#thought-summaries) | 请求 `generation_config.thinking_summaries: auto`，保存 `thought.summary` 中的文字。 |
| [OpenAI Responses](https://developers.openai.com/api/docs/guides/reasoning) | 开启思考时请求 `reasoning.summary: auto`，保存接口返回的推理摘要。OpenAI Chat Completions 不提供相同的摘要开关。 |
| [Anthropic Messages](https://platform.claude.com/docs/en/build-with-claude/thinking) | 开启思考时显式设置 `thinking.display: summarized`，避免新模型默认省略文字。 |
| [OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) | 默认返回可用的推理内容；读取 `reasoning` / `reasoning_details` 的文字，不保存加密部分。 |
| [DeepSeek](https://api-docs.deepseek.com/guides/thinking_mode/)、[Kimi](https://github.com/MoonshotAI/Kimi-K2.5)、GLM、[DashScope](https://help.aliyun.com/zh/model-studio/deep-thinking)、[SiliconFlow](https://docs.siliconflow.cn/docs/api/chat-completions-post)、Ollama 的兼容接口 | 读取 `reasoning_content` 或内嵌 `<think>`。是否启用思考取决于具体模型，不能由存在思考 token 推定会返回文字；如 DashScope 部分模型需通过模型的 `extraBody.enable_thinking: true` 开启。 |

模型配置中的 `extraBody` 可显式覆盖以上摘要设置。接口即使启用了摘要也可能只返回思考用量；此时步骤仍显示「思考过程」及 token 数，展开后说明接口没有返回可读内容，不生成或伪造思考文本。

思考强度与 Jev 的三类概率显示在同一个时间线步骤中，原始判断响应默认折叠。工具开始与返回合并显示，长文本可展开。执行详情中的“可用工具”和“聊天上下文”默认折叠，保存本轮初始请求的工具定义、系统提示和消息上下文。接口重试时会更新为本轮重试使用的初始请求；后续工具轮次仍通过时间线查看。上下文快照最多 128 KiB、200 条消息、100 个工具，超过上限时显示截取提示；列表接口不会传输这些快照。

聊天上下文按来源展示：当前消息单独显示；最近群聊、历史对话、对话摘要、长期记忆与检索结果、群友身份参考、系统提示分别折叠。原始消息快照仍可展开检查，新记录另存组装时的结构和来源；旧记录按已有提示标记进行展示拆分，不补写缺失的内容。

“聊天上下文”标题旁的 **原文** 按钮在弹窗中以可选择的纯文本展示保存的初始请求：系统提示、工具定义、供应商搜索开关，以及按顺序排列的全部已保存消息。图片显示数量而不是原始字节；截取过的快照明确提示并非完整请求，仍保留敏感信息过滤。

`historyMaxTurns` 以用户/机器人问答对计数，一轮是两条历史消息，20 轮允许最多 40 条历史消息；当前输入、记忆/摘要前缀和最近群聊不计入历史轮数。新记录保存实际携带的历史轮数、消息数及当时上限，界面分别标明单位；旧记录只显示已保存消息数。构建请求前和正常回复后的整理阶段都会检查历史上限，按原有分块裁剪策略保留约半个窗口，token 上限也可能更早触发裁剪。引用头现在保留已知发言者的平台 ID（包括机器人本人的引用），无法取得时不猜测。

实际发给模型的最近群聊窗口包含与历史对话重叠的发言和机器人回复，不再跳过同一会话的消息；按记录顺序编号并附时间，保留它们与其他群友发言的穿插关系。提示说明重叠内容属于同一次发言，当前请求在末尾。`chat.groupContext` 支持 0–100 条，内存缓冲保留最近 200 条以容纳触发消息和排队期间的新发言；仍受 `chat.groupContextMaxChars` 和最近 30 分钟限制，排队处理时不包含触发消息之后才收到的发言。快照的结构化最近群聊也最多保存 100 条，但仍受总字节数限制。

当前消息的时间、群名/私聊标记和发言人放在紧邻正文的合并标题中，例如 `【消息｜2026-10-23 周五 18:32｜群「1」｜发言人 会长(平台ID 2)】`。群聊背景、记忆及引用位于这个标题之前；保存到对话历史的用户消息也采用相同布局。执行记录兼容旧版顶部身份标题和新版合并标题。

AGY 和电脑任务完成后，主聊天模型整理结果的轮次也会单独记录，并链接到来源任务。最终回复表示模型生成完成，不代表消息已成功送达聊天。

认证接口为 `GET /api/rollouts`（支持 `?conv=<会话键>`）和 `GET /api/rollouts/:id/history`。每条记录单独保存为 `Yunzai/data/Yunzai-LLM-Plugin/rollouts/<执行ID>.json`，集中索引 `Yunzai/data/Yunzai-LLM-Plugin/rollouts/index.json` 只保留列表所需的状态、模型、费用等元数据和最多 300 字的输入预览，不包含上下文、事件、完整回复或 Jev 响应。列表及会话筛选读取索引，详情按 ID 读取单个文件；详情缓存最多 64 条，未写入的变化另行保留，三秒合并写入时只更新发生变化的详情文件和索引。原子写入及短期恢复日志保证意外退出后可以恢复索引。运行时只使用新格式，不读取旧 `Yunzai/data/Yunzai-LLM-Plugin/rollouts.json`。

旧数据通过一次性离线工具迁移：先正常停止机器人，运行 `node cli/migrate-rollouts.mjs`（可附数据目录参数），迁移全部详情、重建轻量索引并逐文件校验后才删除旧文件，然后启动机器人。失败时原文件保留，可重试；已有更新的独立详情不会被旧副本覆盖。迁移工具不加载机器人或运行时存储模块。

记录结束后保留 30 天，启动时、访问时和每小时按索引清理过期详情文件与图片；不再按总数量或总大小提前删除。页面显示保留期限。每次执行最多保留 500 条 / 256 KiB 事件，超出时显示截断提示。重启后未结束的执行标记为已中断。

记录复用 AGY 的敏感信息过滤，写入和读取时均过滤密钥、私有路径等文本内容；模型接口明确返回的可读思考文本或推理摘要会随每轮模型响应保存，在该步骤内以「思考过程」默认折叠展示，并显示接口报告的思考 token 数；不请求或解密隐藏推理，加密推理、签名和原生会话状态不写入记录。思考文本与普通响应使用相同的脱敏及事件保存上限。旧记录未保存的思考内容无法补回。工具返回给模型的本地 PNG/JPEG/WebP/GIF 图片保存到 `Yunzai/data/Yunzai-LLM-Plugin/rollout-images/<执行ID>/`，通过认证接口 `GET /api/rollouts/:id/images/:image` 显示在工具步骤内，可点击查看原图。每张最多 10 MiB、每次执行最多 64 张 / 64 MiB；无法保存时显示遗漏数量，不主动抓取远程图片 URL。输入上下文仍只记录图片数量。图片原始内容不会经过文本脱敏。详细记录及上下文快照从更新后新开始的执行生效，旧对话摘要仍在“对话”中查看。构建后重启机器人以加载后端记录逻辑。
