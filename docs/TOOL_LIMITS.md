# 工具余量与公网图片

每轮工具结果发给主模型前，追加简短余量：`【工具余量】web_fetch：剩余 2 次；全局剩余 19 次；剩余工具轮次 3。` 单工具余量读取工具实际执行所用的计数器；记忆分别注明修改/读取，图片注明共享图片余量，没有单独次数限制的工具明确显示无单独上限。

`chat.maxToolCalls` 控制一次回复中所有注册工具合计调用尝试数，默认 20，可配置 0–1000，0 禁用注册工具调用。并行调用逐个同步占用总额度，错误参数、失败和未提供的工具请求也消耗全局次数，超过上限的请求不执行。单工具次数仍按该工具原有计数规则扣除。每个并行批次结束后，读取统一的最终余量再附给模型；任一总额度或轮数耗尽时提示直接回复。`chat.maxToolRounds` 仍控制模型调用工具的轮数；供应商内置搜索不经过工具注册表，由原有供应商配置控制。

新增 `send_image({url})`，随最终回复发送公网直链图片原始字节，并把验证过的图片附在工具结果中，支持图片的模型可查看；执行记录也保存预览。需要 `tools.webFetch.enable`，也可通过 `tools.disabled` 单独关闭。不受 webFetch 的私网例外设置影响：只支持公网 HTTP(S)，拒绝内网、含凭证的链接，每跳重定向重新检查地址，连接固定到验证过的 DNS 结果。

图片每张最多 5 MiB、边长最多 16384、总像素最多 4000 万；检查文件魔数、图片尺寸并用 Chromium 实际解码，支持 PNG/JPEG/GIF/WebP。拒绝伪装为图片的网页、损坏图片、不支持的格式、超大下载和异常响应。整个下载/验证限时 20 秒、最多 5 次请求（含重定向）。每次回复最多请求两次（失败也占次数），与 `render_html`、`run_code` 共用回复图片额度；并发下载后再次检查剩余图片位置。成功只表示加入待发送回复，送达仍由正常回复流程决定。
